# 工作台（Workbench）设计

> v2 · 2026-11-16 · 按用户的产品预期重写；v1 设计（用 Agent 预设承载工作台）已被实测证伪：预设拿不掉 host 级注册的工具，不再保留归档。
> 本文是唯一设计依据；取舍理由见 `DECISIONS.md`，实施步骤与实测结果见 `plan.md`。

## 0. 一句话

DSH 每次请求都会把当前可用工具的定义（名称、描述、参数 schema）整包发给模型——本机一个会话里 76 个工具，约 6.4–13k token。本插件把已安装的工具组织成若干「工作台」，每个对话在开始时选定一个：只有 **硬编码必备工具 + 全局工作台 + 当前工作台** 里的工具会随请求发出；其余工具模型只知道名字和用途，需要时申请一次性使用。

## 1. 目标与非目标

### 1.1 目标

1. **省钱**：把每请求的工具定义从几十个降到十几个，固定开销降到原来的 1/3 左右。
2. **提准确率**：模型面对的工具集与当前任务相关，减少选错工具、参数填错。
3. **可控**：用户明确知道「这个对话能用什么」，随时可查、可改配置。
4. **有边界**：工作台之外的工具默认不可调用；要调用必须模型申请、用户批准。

### 1.2 非目标

- 不提供工具的下载、安装、卸载——那是插件市场 / 插件管理的事。本插件只做「已安装工具」的分组与放行。
- 不做 skill 的分组与开关；skill 作为一个普通工具参与工作台分配。
- 不做「按任务自动推荐工作台」（v2 候选）。
- 不与权限档、模型选择、沙箱策略耦合。

## 2. 概念

### 2.1 四类工具

| 类别 | 内容 | 谁能改 | 是否随请求发给模型 |
|---|---|---|---|
| **必备（CORE）** | 17 个硬编码工具 + 插件自带的 `request_tool` | 谁都不能改 | 永远 |
| **全局工作台** | 用户选进去的工具 | 用户（增删） | 永远（唯一一层全局叠加） |
| **普通工作台** | 用户选进去的工具 | 用户（增删） | 仅当它是当前对话的工作台 |
| **未分类** | 已安装、但不在任何工作台里的工具 | 用户（在工具卡片列表里勾选） | 永远不发（除非被申请授权） |

CORE 17 个（硬编码，不可增删）：

`read`、`write`、`edit`、`glob`、`grep`、`pwsh`、`job_list`、`job_output`、`job_kill`、`ask_user_question`、`present`、`todo_write`、`skill`、`compress`、`decompress`、`search_context`、`acp_status`

插件另外固定提供 1 个工具 `request_tool`（模型申请工作台外工具用）。它不在 CORE 名单里，但掩码时无条件放行，合计 18 个必备工具。

> 说明：`present`、`skill` 由当前「模式」（Agent 预设）提供，某些模式（如极简模式）里没有——没有时自然缺席，不报错。CORE 只保证「有就一定放行」，不保证「一定存在」。

### 2.2 有效集

```
有效集 = CORE ∪ 全局工作台 ∪ 当前工作台
```

- **会话开始时冻结**：此后对全局工作台或任一工作台的修改，只影响之后新建的对话。
- 没有选工作台时：`有效集 = CORE ∪ 全局`。
- 全局工作台**不能被选为**「当前工作台」——它是叠加层，不是可选层。

### 2.3 互斥与唯一性

- 一个工具**不能同时**属于全局工作台和任何普通工作台。把工具加入全局时，若它已在某些普通工作台里，提示「将从 3 个工作台移除」并在确认后移除。
- 一个工具**可以**属于多个普通工作台（同一工具在不同工作台各有一份）。
- 工作台名唯一；工具名全局唯一（DSH 注册表本身保证）。
- 工作台数量不设上限。

## 3. 交互

### 3.1 新对话：选工作台

**位置**：输入框右下角、模型下拉框左边（composer 底行 `.standardControls`），与模型下拉同规格的 28px 胶囊。

**样子**：
- 胶囊文本：`工作台：办公` / `无工作台`，左侧是线条工作台图标，右侧是展开箭头
- 点开菜单：`无工作台` + 所有普通工作台（每项右侧显示工具数）；菜单用宿主的浮层 token（`--dsw-menu-surface-fill` + 半透明模糊），浅色深色都跟着宿主走
- 默认值：**上次选择**（`workbenches.json` 的 `lastSelected`）；从未选过时是 `无工作台`
- 只在**会话开始前**可用；开始后按钮保留但禁用，悬停提示「已冻结」，避免用户以为工具丢了（见 D30）。

### 3.2 对话开始后：只读标签

**位置**：会话头部、会话标题右侧（`conversation.session.header.actions`）。

**样子**：
- `工作台：办公`；冻结后带锁图标与工具数（`工作台：办公 · 12 个工具`），悬停显示「（已冻结）」。
- 工作台已被删除时：`工作台：办公（已删除）`。
- 点击不弹窗，信息直接由标签本身传达（只读，没有编辑入口）。
- 没有选工作台的对话：`工作台：无工作台`。

**「开始」的定义**：这个会话第一次发出消息（会话日志里第一次出现 `turn/start`）。恢复一个旧会话永远是「已开始」状态，标签只读。

### 3.3 设置页「工作台」分区

**入口**：设置 → 工作台（`settings.section`，order 18）。整页自上而下三块：标题与说明、工作台卡片行、工具卡片列表。

页面上只有一个「工作台」标题，下面的工作台分区不再重复标题，只留一行提示（「点卡片切换当前工作台 · 拖动卡片排序」）；工具分区是「工具」+ 一行提示，标题用 `.dswb-sectionTitleText` 固定 `flex:none; white-space:nowrap`，不会被右侧提示挤成两行竖排。说明文字只保留关键信息：对话开始时冻结工具集、其余工具在提示里留一句话用途、模型申请后由用户批准。

**工作台卡片行**（`dswb-row`）：

1. 左侧是可横向滚动的卡片带（`dswb-boardScroll`）：
   - 第一张固定是**全局工作台**卡片：线条工作台图标 + 名称 + 「其中的工具在任何对话里都可用」+ 工具数。不可删、不可拖动。
   - 其后是各普通工作台的卡片：图标、名称、介绍（没填时显示「未填写介绍」）、`N 个工具`；右上角是铅笔（改名/改介绍，弹窗）与垃圾桶（四秒内再点一次才删）。
   - 点卡片 = 选中它，下方工具列表切换到「这个工作台里的工具」；选中的卡片有强调描边。
   - 拖动普通卡片可以调整顺序，落盘为 `benches` 数组顺序（`POST /api/bench/reorder`）；全局卡片永远第一。
2. 右侧固定一张**新建**卡片（`+`，76px 宽，只放一个加号与「新建」），不随横向滚动移动：点开弹窗填名称（必填，≤30 字）与介绍（可空，≤200 字），确定后新建并自动选中，新卡片排在卡片带最右（`POST /api/bench`）。

**工具卡片列表**（`dswb-toolsBox`，独立边框、单列、竖向滚动）：

- 一张卡片一个工具：名称、来源徽标、一句话用途（两行截断）、右侧勾选圆点。
- 点卡片 = 把该工具加入/移出当前选中的工作台（`POST /api/bench/tools`）；选中全局工作台时点卡片就是增删全局工具（`POST /api/global`）。
- 已在全局工作台里的工具，在普通工作台里显示为已选并置灰，点了无效（悬停提示「已在全局工作台，不能重复分配」）。
- 顺序由配置里的 `toolOrder` 决定，拖动卡片即重排（`POST /api/tools/reorder`）；**切换工作台不改变工具顺序**，只有勾选状态变化。

**来源徽标**（尽力而为，见 D33）：MCP 工具 `mcp__<server>__<tool>` 显示 `<server> · MCP`；CORE 与常见内置工具显示「内置」；其余取工具名首段（`dsw_`/`dsh_` 前缀时取第二段）当插件名。

**新增/修改弹窗**：名称 input + 介绍 textarea，Enter 提交、Esc 取消，遮罩点击不关闭；提交失败时错误显示在页面上。

**配色**：所有颜色取自宿主 design token（`--dsw-*`），浅色与深色共用同一套规则；不写死颜色、不用不存在的变量名配白色兜底（见 D34）。

**高度与滚动**（见 D35）：宿主把设置分区塞进一个固定高度的面板，面板会把超出自身底边的内容**直接裁掉**，且插件拿不到该面板的高度（宿主样式是 hash 类名的 CSS-in-JS，静态不可达）。所以整页自己限高、自己滚：

- `.dswb-page`：`display:flex; flex-direction:column`，`max-height:100%`，`height:100%`，`max-height:min(100%, calc(100dvh - 260px))` 作为兜底，`overflow-y:auto`，底部内边距 28px。这样无论宿主给多高，页面都不会把底部内边距和最后一张卡片挤出可视区。
- 两个区块是 `.dswb-group`（`display:flex; flex-direction:column; min-height:0`）：工作台行 `flex:0 0 auto` 不收缩；工具区块 `flex:0 1 auto` 先收缩，其中的 `.dswb-toolsBox` 再 `flex:1 1 auto; min-height:120px; max-height:440px` 自己竖向滚动。空间再不够时整页滚动（`overscroll-behavior:contain`，滚到底不把滚动传给外层对话框）。
- 直接子元素一律 `flex:none`，避免默认 `min-height:auto` 让内容撑破容器；**可收缩性必须写在真正承载工具盒的那个 section 上**，写在 `.dswb-toolsBox` 上无效（它不是 `.dswb-page` 的直接子元素）。
- 兜底量测：`useClippingLimit()` 在 layout effect 里从页面向上找第一个「会裁剪」的祖先（`overflow-x/y` 非 `visible`），取它的内容盒高度作为 `max-height` 的内联值。这个内联值只会**收紧**样式表已经算出的结果（先读 `getComputedStyle(node).maxHeight` 再取 min），所以宿主将来给了确定高度、或样式表兜底值更小时都不会被撑大；量不到裁剪祖先时什么都不写，交给 CSS。

### 3.4 模型申请工具

**触发**：模型调用 `request_tool({ tool, reason })`。

**流程**：
1. 校验：工具不存在 → 直接返回「没有这个工具」；工具已可用 → 返回「已经可用，直接调用」；否则继续。
2. 弹原生审批卡片（与沙箱命令批准同一套 UI）：
   - 标题：`允许使用工作台外的工具？`
   - 正文：工具名、一句话用途、模型给的理由、以及「允许后本轮对话内可用，轮次结束自动收回」。
   - 按钮：`允许一次` / `拒绝`
3. 允许 → 本轮内该工具加入有效集，下一次请求带上它的完整 schema，模型可以调用（本轮内可多次调用）。
4. 拒绝 → 返回拒绝原因，模型本轮不能再用它。
5. 轮次结束 → 自动收回。

**用户看到的效果**：聊天里出现一张确认卡；同意后模型立刻能用那个工具干活；这一轮结束后权限自动消失，下一轮再想用得重新申请。

## 4. 数据与状态

### 4.1 配置文件

`~/.dsh/plugin-data/dsh-toolset/workbenches.json`（`DSH_HOME` 有值时取 `$DSH_HOME/plugin-data/dsh-toolset/workbenches.json`）

```json
{
  "version": 1,
  "lastSelected": "bm3k1a2",
  "global": { "tools": ["mcp__github__search_code", "x_search"] },
  "toolOrder": ["univer_sheet", "univer_doc", "univer_slide", "x_search"],
  "benches": [
    {
      "id": "bm3k1a1",
      "name": "办公",
      "description": "表格、文档与幻灯片的日常处理",
      "tools": ["univer_sheet", "univer_doc", "univer_slide"],
      "createdAt": 1763316000000
    },
    {
      "id": "bm3k1a3",
      "name": "研究",
      "description": "",
      "tools": ["web_search", "web_fetch", "x_search"],
      "createdAt": 1763316300000
    }
  ]
}
```

- 唯一真相在这个文件；没有第二份派生配置。
- `id` 由插件生成（`b` + 36 进制时间戳 + 计数器），客户端只当作不透明标识。
- 工具用名字引用（DSH 工具名全局唯一）。
- `lastSelected` 是「上次新建对话时选的工作台」，`null` 表示无工作台。
- `benches` 的数组顺序就是设置页卡片行的顺序；`toolOrder` 是工具卡片的显示顺序（只影响 UI，不参与掩码）。两者都由拖动排序写入，未列在 `toolOrder` 里的工具按名字排在后面。
- `description` 是工作台的一句话介绍，可空，上限 200 字符；只做展示，不影响掩码。
- `createdAt` 是毫秒时间戳（与 `Date.now()` 对齐，避免 ISO 串解析分歧）。
- 不存在的工具名在读取时保留但不生效（对应插件被卸载后回来还能恢复），UI 标「已失效」；`toolOrder` 里也故意保留未知名字，重装插件后顺序能复用。
- 名称长度上限 30 个字符（按 `String#length` 计，即 UTF-16 码元；中文按字计）。

### 4.2 会话事件与投影

工作台是**会话属性**，不是 DSH 的 Agent 预设（模式）。存储照抄模型选择的成熟做法：写会话插件事件 + 注册投影。事件类型必须带 `plugin:` 前缀——`appendPluginRecord(session, type, data)` 要求如此（生态惯例，见 action-cards）。

| 事件 | 何时写 | 载荷 |
|---|---|---|
| `plugin:dsh-toolset/selected` | 用户在会话开始前选择/切换时 | `{ benchId, name, at }`，`benchId` 为 `null` 表示无工作台 |
| `plugin:dsh-toolset/frozen` | 会话第一次发出消息时 | `{ benchId, name, core: [...], global: [...], bench: [...], allowed: [...], at }` |

- `frozen` 存**解析后的工具名清单**，不是引用。因此工作台后来被改、被删，都不影响这个对话继续按快照工作。`allowed` 是实际放行的工具名（已与 `restrictableNames` 求交、不含 `request_tool`），头部标签的工具数用它，不会把未安装的 CORE 名额算进去。
- 投影键 `workbench`，视图字段（扁平）：`{ benchId, name, selected, started, core, global, bench, allowed, deleted }`；`deleted` = 快照里的 benchId 在当前配置里已不存在。`selected` 区分「还没选过」与「主动选了无工作台」：前者视图回落到 `lastSelected`（与实际生效的默认工具集一致），后者保持空。
- 客户端通过 projection face 读，host 通过 `stateOf(session)` 读。
- 首次写入发生在 `turn/start` 的发布过程中，此时会话拒绝重入 append，所以 `frozen` 用 `queueMicrotask` 延后一条微任务写入。

### 4.3 会话内授权（内存态）

- `grants: Map<sessionId, Set<toolName>>`，只在进程内，不写盘、不参与 replay。
- 进程重启后所有临时授权消失——符合「临时」语义。

## 5. 运行时机制

### 5.1 不碰注册表

所有工具照旧由各自插件在 host 层注册；工作台**不改变注册行为**，只在 agent 作用域上打掩码。这样申请授权时才能把工具「临时放回来」——如果靠「不注册」来隐藏，就永远放不回来（生态先例 tool-guardian 也走注册+路由）。

### 5.2 掩码

在 agent 的作用域上调用 `tools.restrict({ allow })`：

- `allow` = `(CORE ∪ global ∪ bench ∪ grants[session]) ∩ restrictableNames`，并额外无条件加入 `request_tool`。
- **必须先按 `restrictableNames` 过滤**：`tools.restrict()` 对未知名字会抛错（`tools.restrict() names unknown global tool ...`）。`restrictableNames` 是 `ctx.tools.view(agent)` 提供的、当前作用域里可被掩码的名字集合；CORE 里可能不存在的工具（如极简模式下的 `present`）由它过滤掉。
- **必须先挂好 Agent 预设再 restrict**：预设层注册的工具虽然会被 restrict 掩掉，但必须先存在，否则名字校验失败。
- 改掩码要**先 dispose 旧的再建新的**：同一层多次 restrict 取交集，不能靠叠加放宽。
- **只在 `turn/start` 施加，不在挂载时施加**：插件加载时会对已存在的会话逐个 `attach()`，此刻状态里还没有解析出的工具集，若立刻 restrict，allow 只剩 `request_tool`，本轮请求的工具集会变成空的可见集。DSH 的 `in-history` 投影会把历史上出现过的定义都标成 `defer_loading: true`，服务端因此返回 `400 INVALID_REQUEST: tools: at least one tool must have defer_loading=false. All tools cannot be deferred.`——桌面端装上插件的当轮就踩过这个坑。选择工作台（`POST /select`）同理，只记录、不立即掩码。
- **allow 至少要留下一个工作台工具**：`allowedNames` 为空、或只剩 `request_tool` 时跳过 restrict 并记警告，等下一次 `turn/start` 再试；空可见集正是上面那个 400 的触发条件。
- 掩码挂在 agent 作用域，会话结束随作用域自动释放。
- 配置降级（文件损坏）时**整体不打掩码**：宁可多给工具，也不能让用户装完插件就不可用。

### 5.3 生效点

请求装配顺序是：`tools.resolve()` → `systemPrompt.assemble()` → 组装请求体（顶层 `tools`）。被 restrict 的工具**根本不进 `tools` 数组**，所以省的是实打实的 token；模型侧表现为「这个工具不存在」。

> 验收只能看**请求体**：`tools.view()` 反映的是注册表而不是掩码结果，不能作为「工具已被隐藏」的证据。

### 5.4 目录注入

用 `systemPrompt.section`（名 `workbench:catalog`，order 9000）加一段：

```
## 其他已安装的工具
当前工作台：「办公」。下列工具已安装但本对话不可用；确实需要时，调用 `request_tool` 申请一次授权，用户同意后本轮内可以直接使用。
- univer_sheet：在电子表格工作簿里读取、写入和计算…（工作台「办公」）
- web_search：联网搜索…（工作台「研究」）
- x_search：搜索 X 上的帖子…（未分类）
```

规则：
- 只列**不在有效集里**的已注册工具（在有效集里的已有完整 schema，不重复）。
- 每行 `名字：一句话用途（归属）`；归属是 `全局` / `工作台「X」` / `未分类`。
- 「一句话用途」取工具描述的第一句（遇 `。．.；;!?！？` 截断），去掉换行、截断到 80 字（超出加 `…`）；无描述时只留名字。
- 目录随会话的工具集变化；授权后该工具从目录消失、出现在 `tools` 里。
- 量级：实测 14 行、占 521 字符（约 200 token）；工具装得多的机器上大致每行 20 token。

### 5.5 申请与授权

1. `request_tool` 校验后调用 `ctx.approval.request({ agent, toolName, reason, displayReason })`——原生审批卡片，只有「允许一次 / 拒绝」两个结果（`allowed-once` / 其它），无「永久允许」。
2. 允许 → `grants[session].add(tool)` → 重建 restrict → 同一轮的下一个请求就带上该工具。
3. 轮次结束（`turn/end`）→ 清空该会话 grants → 重建 restrict。
4. 只在本轮有效：不写会话、不跨轮、不跨会话、不继承给子代理。

### 5.6 子代理

子代理是独立会话（`agent.id === session.id`）。创建子代理时，用父会话已冻结的 allow 集作为子代理的初始 allow（同样 restrict 施加），保证「父能用的子也能用，父不能用的子也不能用」；父会话当轮临时批准的 grant **不**继承。子代理内部的申请授权只作用于它自己。

### 5.7 缓存影响（要如实告诉用户）

- 请求体前缀顺序（推断）：`tools` → `system` → `messages`。工具 schema 变化会让从第一个变化 token 起的缓存全部失效。
- 会话内工具集稳定 → 每次会话只在开始时「定型」一次，之后每轮都能命中前缀缓存。
- 一次申请授权会造成两次变化（放开一次、轮末收回一次），各带来一次前缀 miss。频繁申请会明显变贵——这是「临时授权」的代价。
- 全局/工作台改动不影响已开对话，正是为了不制造这种 miss。
- 标题生成用的是另一个 agent，不受掩码和目录影响。

## 6. 边界与错误处理

| 情况 | 行为 |
|---|---|
| 会话已开始，用户想换工作台 | 不允许；胶囊已消失，头部只读。要换只能新开对话 |
| 修改全局/工作台 | 只影响新对话；已开对话按冻结快照继续 |
| 删除一个正在被使用的普通工作台 | 允许；老对话按快照继续，头部标签显示「（已删除）」，可继续工作 |
| 删除工作台时它没有任何工具 | 允许（空工作台合法） |
| 工作台里的工具被卸载 | 快照里的名字解析不到 → 静默忽略；设置页标「已失效」 |
| 工具已在全局，又加入普通工作台 | 禁止；选择器置灰。从全局移除后才能加入普通工作台 |
| 加入全局的工具已在普通工作台 | 提示「将从 N 个工作台移除」，确认后移除 |
| 模型申请不存在的工具 | 返回「没有这个工具」，不弹卡片 |
| 模型申请已可用的工具 | 返回「已经可用，直接调用」，不弹卡片 |
| 模型申请后一直不调用 | 轮次结束自动收回，无残留 |
| 配置文件损坏/非法 | 不覆盖原文件，报错并保留上一版；工作台功能退化为「全部工具可用」并提示 |
| 没有安装任何可分配工具 | 设置页显示空状态；对话照常（只有 CORE） |
| `run_code`（PTC 模式） | 保留名，不能被 restrict；它派发的子调用仍受工具集约束 |
| 审批被外部直接拒绝（如 `--approval-policy never`） | `request_tool` 返回「用户没有批准」，不阻塞对话 |
| 旧会话（本插件安装前创建） | 没有 `plugin:dsh-toolset/*` 事件 → 视为「无工作台」，按 CORE ∪ 全局 工作 |

## 7. 验收标准

1. **默认值**：新建对话时胶囊显示上次选的工作台；从未选过显示「无工作台」。
2. **选择与锁定**：胶囊可点可用；发出第一条消息后胶囊禁用并提示「已冻结」、头部出现只读标签；刷新页面后标签仍在。
3. **只发当前工作台**：任一对话的请求体 `tools` 数组里，只有 CORE ∪ 全局 ∪ 当前工作台；用请求体或 token 面板核对工具数下降。
4. **设置页**：工作台卡片行可横向滚动、全局卡片固定最左、「+」卡片固定最右；点卡片切换编辑对象；新建/改名称/改介绍/两次确认删除；点工具卡片增删工具；全局与普通工作台互斥且全局工具在普通工作台里置灰；工作台与工具都能拖动排序且刷新后顺序保持；浅色深色下配色都正确。
5. **目录**：系统提示里出现不可用工具的「名字：用途（归属）」；有效集里的工具不出现。
6. **申请**：模型调用 `request_tool` → 弹卡片 → 允许后本轮能调用、轮末收回；拒绝后模型收到拒绝原因。
7. **冻结**：对话进行中改全局/工作台，该对话的工具集不变；新对话才变。
8. **删除工作台**：老对话继续可用，标签显示「（已删除）」。
9. **子代理**：子代理可用工具与父会话一致。
10. **回归**：不装本插件时 DSH 行为完全不变；装了之后不选工作台的对话，行为等于「CORE ∪ 全局」（而不是全部工具）。
11. **热装安全**：插件装到已运行的会话后，下一个 `turn/start` 才施加掩码；任何时刻都不能让可见工具集变成空集（空可见集会触发 `400 INVALID_REQUEST: tools: at least one tool must have defer_loading=false`）。

## 8. 代价与风险

### 8.1 工程代价

- 需要**host 插件**：配置读写、会话事件、投影、restrict 引擎、目录 section、`request_tool`、审批集成。纯 ESM，无构建步骤（`main` 直接指向源码）。
- 需要**客户端插件**：胶囊、头部标签、设置页三处 UI。以手写浏览器模块交付（`window.__ModuleLoader__.load` + React 基线模块），不引入打包器，也就不用跟 DSH 的构建工具链版本。
- 需要一条**端到端验证**：真实 headless 会话 + mock 模型，断言请求体里只剩允许的工具（见 `plan.md` §3）。

### 8.2 运行代价

- 每个对话开始时要算一次 allow 列表并打掩码（毫秒级，可忽略）。
- 目录常驻约 200–1200 token/请求（取决于没装进工作台的工具数量）。
- 授权引发的缓存 miss（见 5.7）。

### 8.3 产品代价

- 用户必须理解「工作台」这个概念；默认沿用上次选择可能让人误以为工具丢了（靠头部标签和目录缓解）。
- 模型可能不会主动申请工具（取决于模型对 `request_tool` 的理解）；需要在工具描述里写清楚使用场景。
- 没被分配进任何工作台的已安装工具永远不会随请求发出，除非用户主动分配或模型申请——设置页用「工具卡片未勾选」直观表达这一点。

### 8.4 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 客户端插槽（composer / header）被未来 DSH 版本改动 | UI 失效 | 只用公开 slot 名；P0 已实测三处都能渲染 |
| `tools.restrict()` 在 agent 创建时的可用性变化 | 掩码失效 | 端到端脚本用请求体断言；API 变化时第一时间暴露 |
| restrict 与预设层叠加时的名字校验顺序 | 会话创建失败 | 先挂预设、再按 `restrictableNames` 过滤、最后 restrict |
| 工具描述质量差，目录里「一句话用途」不可读 | 模型申请不到对的工具 | 截断规则 + 对无描述工具用名字兜底 |
| 缓存收益未用真实账号量过 | 无法证明省钱幅度 | 记录请求体字节数的对照测量；有真实账号时补 `cacheReadTokens` |

## 9. v2 候选

- 按任务自动推荐工作台（新建对话时预选）。
- 按 MCP 服务器整体开关（一次开关一个服务器的全部工具）。

## 10. 插件形态与安装

DSH 把插件当作 profile 的一个 bundle 层：package.json 声明 `dsh.bundle.patch`，patch 文件里 `insert` 一行本插件；profile 的 `dsh.profile.bundles` 列出包名即可挂载。

**目录结构**：

```
dsh-toolset/
  package.json        # main/exports/dsh.bundle.patch/files
  cordis.patch.yml    # insert: [{ id: dsh-toolset, name: 'dsh-toolset', config: {} }]
  icon.svg            # ≤256 KiB
  locale/{en,zh}.json # 插件管理器里的标题与描述（不激活也能显示）
  src/                # host 实现，纯 ESM
  client/            # P2 客户端 bundle（exports["./client"]）
  test/               # node:test 单测
  scripts/e2e/        # 端到端验证（临时 DSH_HOME + mock 模型）
  docs/
```

**安装**：

- 开发机 / 自定义 profile：`dsh plugin --profile <profile> add <path-or-package>`。该命令把参数转发给 profile 目录里的 pnpm，装完后自动把带 `dsh.bundle` 的新依赖追加进 `dsh.profile.bundles`——不需要手改 profile 文件。本地目录以 `link:` 记入依赖，等于 junction，改源码重启即生效。
- 桌面应用（desktop profile 由 Electron 独占管理，CLI 会拒绝）：用 `plugin_manager` 的 `install_bundle`。
- 卸载：`dsh plugin --profile <profile> remove dsh-toolset`（桌面走 `plugin_manager` 的 `remove_bundle`）。

**能被 DSH 识别的 manifest 字段**（实测）：`main` / `exports`（`exports["./client"]` 决定客户端入口）、`dsh.bundle.patch`（字符串或数组，路径相对包目录）、`dsh.bundle.platforms`、`dsh.client`（仅 `platform`/`inject`/`external`/`immediately`）、`dsh.compatibility`。`dsh.manifestVersion` 目前没有读取点，写它只为将来兼容。
