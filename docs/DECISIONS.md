# 决策记录

> v2 · 2026-11-16。每条记录：**决定 / 理由 / 代价**。状态标记：`采纳`、`作废`、`待定`。
> v1 的 D1–D18 全部作废（v1 归档文档随「去掉过时内容」一并删除），本文 E 节保留逐条处置。

## A. 身份与存储

### D1 工作台是「会话属性」，用会话事件 + 投影存储 · 采纳

- **决定**：用户选定工作台时写 `plugin:dsh-toolset/selected` 会话事件；第一条消息发出时写 `plugin:dsh-toolset/frozen`（含解析后的工具名）；注册 session projection `workbench` 提供读模型。事件类型必须带 `plugin:` 前缀，这是 `appendPluginRecord` 的要求。
- **理由**：工作台天然是「这个对话」的属性。DSH 的模型选择（`model/selection` + `modelSelection` 投影）就是这么做的，照抄最稳；事件参与 replay，换设备/重启后仍在；不需要改 Agent 预设，不需要为每个工作台生成一个 preset，不需要重启 DSH。
- **代价**：客户端要自己渲染选择器；host 要自己维护投影。

### D2 有效集 = CORE ∪ 全局 ∪ 当前工作台，首条消息时冻结 · 采纳

- **决定**：见 `design.md` §2.2。冻结的含义是：此后改配置只影响新对话。
- **理由**：工具集在会话中途变化会破坏前缀缓存、让模型突然失去工具，用户体验差；「开始时定」与「开始时选工作台」是同一个心智模型。
- **代价**：用户改了配置后在旧对话里看不到效果，需要新开对话（靠文档与设置页文案说明）。

### D3 CORE 17 个 + `request_tool` · 采纳

- **决定**：`read/write/edit/glob/grep/pwsh/job_list/job_output/job_kill/ask_user_question/present/todo_write/skill/compress/decompress/search_context/acp_status`，加插件自带的 `request_tool`，共 18 个永远可用，用户不能增删。
- **理由**：前 11 个是「干活」的最低需求；`present` 交付文件；`skill` 加载技能；4 个上下文管理工具保证长对话不会因为工作台没包含它们而丧失压缩能力。
- **代价**：每个对话固定多 18 个工具定义（约 2–3k token），这是地板价。

### D4 全局工作台唯一、不可选、永远叠加 · 采纳

- **决定**：全局工作台不是「一种可选工作台」，而是一个叠加层；下拉里不出现它。
- **理由**：与用户的预期一致（全局是公共底座），也避免「选了全局 + 又选了普通」这种双重语义。
- **代价**：全局里的工具在所有对话里都发，无法按对话关掉（要关就移出全局）。

### D5 全局与普通互斥，普通之间可重叠 · 采纳

- **决定**：一个工具不能在全局和任何普通工作台同时存在；可以同时属于多个普通工作台。
- **理由**：互斥保证「有效集」无歧义；重叠允许同一工具服务多个场景。
- **代价**：把工具移入全局时要从若干工作台摘掉，需要确认提示。

### D6 未分类 = 已安装且不在任何工作台 · 采纳

- **决定**：未分类不是工作台，只是一个待分配池；其中的工具默认不发给任何对话（除非被申请授权）。
- **理由**：与「只发有效集」一致；新装工具默认不偷偷进入任何对话。
- **代价**：用户不主动分配的话，新工具等于不可用；设置页要靠数字提示。

### D7 `workbenches.json` 是唯一真相 · 采纳

- **决定**：配置只存 `~/.dsh/plugin-data/dsh-toolset/workbenches.json`，不改 profile 的 patch 层、不生成任何派生配置。
- **理由**：v1 的「sync 生成 preset」是整条复杂度来源，而且已被证伪为不必要（见 D8）。
- **代价**：所有读写都要过本插件的服务层（好在只有一处）。

## B. 运行时

### D8 用 `tools.restrict({ allow })` 打掩码，不靠「不注册」 · 采纳

- **决定**：所有工具照旧全局注册；在 agent 作用域上 restrict，把不在有效集里的工具移出可见集合。
- **理由**：restrict 的效果是工具**根本不进请求体**（省 token）；而且因为工具还在注册表里，申请授权才能把它临时放回来。若靠不注册隐藏，就再也放不回来。
- **代价**：依赖 restrict 的语义细节（作用域、名字校验、disposer）。

### D9 allow 列表必须先按 `restrictableNames` 过滤，且先挂预设再 restrict · 采纳

- **决定**：构造 allow 时取 `(CORE ∪ global ∪ bench ∪ grants) ∩ restrictableNames`，再无条件加入 `request_tool`；在 agent 创建、预设已挂载后再施加。
- **理由**：restrict 对未知名字抛错；`restrictableNames` 是 `tools.view(agent)` 给出的、当前作用域里可被掩码的名字集合，正好能滤掉本模式里不存在的 CORE 工具（如极简模式没有 `present`）。预设层注册的工具属于 agent 的父作用域，必须先存在才能被点名（点名是合法的，会生效）。
- **代价**：allow 的构造要等注册表就绪；会话创建早期注册的工具可能与 allow 不同步（见 D10）。

### D10 改掩码一律「dispose 旧的再建新的」 · 采纳

- **决定**：每次工具集变化都先 dispose 上一次的 restriction disposer，再用新 allow 重建。
- **理由**：同一层多次 restrict 取**交集**，叠加只会越收越紧，无法放宽。
- **代价**：每次变化都是一次作用域写操作（开销可忽略），但会触发一次工具集变化（缓存影响见 D13）。

### D11 目录用 `systemPrompt.section` 常驻，只列不可用工具 · 采纳

- **决定**：每轮注入一段 `workbench:catalog`：当前工作台 + 不可用工具的 `名字：一句话用途（归属）`。
- **理由**：需求明确要求「模型能看到所有工具的名称和大概用途」；section 是纯文本、可控、随会话变化。只列不可用工具避免与 `tools` 重复。
- **代价**：实测 14 行时 +521 字符（约 200 token）；工具装得多的机器上约每行 20 token。

### D12 `request_tool` 是插件自带的必备工具 · 采纳

- **决定**：签名 `request_tool({ tool: string, reason: string })`；永远在 allow 里。
- **理由**：申请入口必须随时可用；放进 CORE 会让它随 profile 走，而它本来就是本插件的一部分。
- **代价**：多一个工具（已计入 18 个）。

### D13 授权 = 原生审批 + 重建 restrict，本轮有效、轮末收回 · 采纳

- **决定**：`ctx.approval.request`（只有「允许一次 / 拒绝」）；允许后 `grants[session].add(tool)`，重建 restrict；`turn/end` 清空并重建。
- **理由**：原生卡片体验最好、有审计事件；重建 restrict 让模型拿到**真实 schema**（比元工具转发强）；「本轮有效」避免同一工具连用两次要弹两次窗，同时不跨轮、不跨会话，符合「临时」语义。
- **代价**：每次授权造成两次工具集变化（放开、收回），各一次前缀缓存 miss；授权不持久化（重启即失效），这正是想要的。

### D14 不做「元工具转发」式的代调用 · 作废（曾评估）

- **决定**：不把目标工具包进 `request_tool` 里代执行。
- **理由**：模型拿不到真实 schema，参数只能靠猜；呈现层会把一次工具调用变成嵌套调用；仍有二次审批风险。
- **代价**：接受 D13 的缓存代价。

### D15 子代理继承父会话的 allow 集 · 采纳

- **决定**：创建子代理时用父会话冻结的 allow 作为子代理的初始 allow（同样 restrict 施加）。
- **理由**：子代理不继承父 agent 的 restrict（作用域不互链），不显式传播就会「父不能用的子能用」，破坏边界。
- **代价**：子代理的申请授权只作用于它自己，不回流给父。

### D16 全局/工作台改动只影响新对话 · 采纳

- **决定**：配置变更不回溯已冻结的会话。
- **理由**：同 D2；避免缓存 miss 与「工具突然消失」。
- **代价**：改完配置要新开对话才看得到效果。

### D17 删除工作台不回溯已有会话 · 采纳

- **决定**：老对话按冻结快照继续；头部标签显示「（已删除）」；不禁止删除正在使用的工作台。
- **理由**：快照里存的是工具名，不依赖工作台存在；禁止删除会让用户被历史对话「锁死」。
- **代价**：会存在「引用一个已不存在配置」的旧对话，标签要如实标注。

## C. 交互

### D18 选择器在 composer，只读标签在会话头部 · 采纳

- **决定**：新对话用输入框右下角、模型下拉左边的胶囊（`conversation.input.right`，与 `conversation.input.model` 相邻）；开始后胶囊禁用（保留可见，见 D30），标签出现在 `conversation.session.header.actions`。
- **理由**：用户明确要求「模型下拉旁边」与「会话名称旁边、和切换模式一样」；这两个 slot 都是公开的，不需要改 DSH 布局包。
- **代价**：两处 UI 要各写一份状态读取（都走同一个投影 face）。

### D19 默认沿用上次选择 · 采纳

- **决定**：新对话默认 `lastSelected`；`null` = 无工作台。
- **理由**：与「记住上次选的模型」一致，减少每次选择的摩擦。
- **代价**：忘记改会静默沿用上次的工作台；靠头部标签 + 目录缓解。

### D20 设置页工具选择器 = 搜索 + 平铺 + 筛选 chips · 采纳（P2 缩减为最小版）

- **原决定**：不做按来源/按用途分组；列表行带来源标签与归属标记。
- **实际交付**：平铺复选框清单，勾选即写入；搜索、筛选 chips、来源标签未实现（`plan.md` §4 与 `design.md` §3.3 已按交付改写）。
- **理由**：DSH 注册表不记录工具来源（register 只存 definition 与 when），分组只能靠手工映射，且新插件必落「未知来源」；搜索 + 平铺永远准确。
- **代价**：70–80 条要滑，依赖搜索。

### D21 设置页是 v1 的主入口，不做命令集 · 采纳（推翻 v1 的 D9）

- **决定**：v1 就做图形设置页；不提供 `/toolset` 之类的 CLI 作为主路径（`/workbench` 只作为无 UI 环境下的兜底入口存在）。
- **理由**：用户要的就是设置页；工作台只能在会话开始时切换，命令切换本身就与该规则冲突。
- **代价**：客户端 UI 成为 v1 的一部分，需要手写浏览器模块并跟 DSH 客户端插槽版本走。

### D22 包名与数据目录 · 采纳

- **决定**：包名 `dsh-toolset`；配置在 `~/.dsh/plugin-data/dsh-toolset/`。
- **理由**：与项目名一致；plugin-data 是 DSH 给插件存用户数据的约定目录，不污染 profile。

## D. 工程

### D23 客户端与 host 分成一个包的两个入口 · 采纳（实现方式已修正）

- **决定**：`main: src/index.js`（host，纯 ESM）+ 将来的 `exports["./client"]`（客户端，手写浏览器模块，`window.__ModuleLoader__.load`）；两者同包发布。
- **理由**：生态里 better-sidebar 等就是这么做的；一个包便于安装与版本对齐。本仓库不引入 TS/打包器：host 只有几百行，客户端 UI 也就三处，手写 ESM 省掉整条构建链，也避免与 DSH 的 tsdown/React 版本绑定。
- **代价**：客户端没有类型检查与模块打包，代码里只能 require 基线模块（react、react/jsx-runtime、react-dom、`@deepseek-ai/dsh-client-ui-primitives` 等）。

### D24 配置写入原子化、失败不破坏原文件 · 采纳

- **决定**：写临时文件 → 校验 → rename；保留上一版备份；损坏时退化为「全部工具可用」并提示。
- **理由**：配置文件是唯一真相，坏一次整个功能不可用。
- **代价**：多几行代码，值得。

### D25 工具来源标签只做尽力而为 · 暂缓

- **原决定**：`mcp__<server>__<tool>` 解析出 MCP 服务器名；其余标「内置」或「插件」。
- **实际**：0.2.2-rc.1 的 `tools.view().registrations` 只给 `definition` 与拦截器，没有来源字段，也不保证 `mcp__` 命名；不做标签，等 DSH 提供来源元数据再补。
- **代价**：未分类清单里看不出工具来自内置、MCP 还是插件。

### D26 文档名与目录收敛为英文小写 · 采纳

- **决定**：`docs/design.md`（设计）、`docs/plan.md`（实施与实测进度）、`docs/DECISIONS.md`（决策，保留大写以贴合生态惯例）、`docs/research/`（调研报告）。中文文件名不再使用。
- **理由**：`README`、`package.json` 与工具链都按 ASCII 处理路径，中文名在命令行、补丁、链接里反复转义；统一小写也避免大小写不敏感文件系统上的改名失败。
- **代价**：旧链接失效；文档内部引用一律用新名。

### D27 时间戳用毫秒数字、名称上限 30 字符 · 采纳

- **决定**：`createdAt` 与事件载荷里的 `at` 都是 `Date.now()` 的毫秒数；工作台名上限 30 个字符（`String#length`）。
- **理由**：数字时间戳与运行时保持一致，不引入 ISO 解析与本地时区的分歧；30 个字符对应设置页输入框的实际宽度。
- **代价**：手写 `workbenches.json` 时数字不直观，靠设置页维护。

### D28 验收只看请求体，不看 `tools.view()` · 采纳

- **决定**：任何「工具已被隐藏」的判断都以模型请求体顶层 `tools` 为准；`tools.view()` 反映注册表而非掩码结果，不作为证据。
- **理由**：P0 实测中 `view()` 在 restrict 之后仍列出全部工具，只有请求体才反映真实发送内容。
- **代价**：端到端验证必须挂 mock 模型或抓请求（`scripts/e2e` 即为此）。

### D29 插件不打包、无构建步骤 · 采纳

- **决定**：host 直接以 `main: src/index.js` 发布源码；客户端将来以 `client/client.js` 手写浏览器模块交付；不使用 tsdown/esbuild/tsc。
- **理由**：DSH 只读 `main`/`exports`，不要求构建产物；不加构建链就没有「忘了 build」的失效模式，也让 `link:` 安装的改动立即生效。
- **代价**：没有类型检查；客户端只能用基线模块表里的依赖。

### D30 冻结后胶囊保留但禁用；未选过的对话在投影里显示默认工作台 · 采纳

- **决定**：第一条消息之后 composer 胶囊不消失，改为禁用并提示「已冻结」；投影在没有任何 `selected` 事件时回落到 `lastSelected`（用 `selected` 字段区分「没选过」与「主动选了无工作台」）。
- **理由**：胶囊消失会让用户以为工具丢了（正是 D19 的代价）；投影回落是因为 `mask` 在没有选择时本来就按 `lastSelected` 发送，展示必须与真实工具集一致——这一条是目视验证时发现的实现 bug，不是设计变更。
- **代价**：投影多一个 `selected` 布尔字段；`lastSelected` 在会话创建后、首条消息前被改时，UI 会显示新值而会话仍按创建时的值发送（窗口极短，且首条消息会写入 frozen 快照）。

### D31 掩码只在 `turn/start` 施加，挂载与选择时只记录 · 采纳

- **决定**：`attach()`（插件加载时对已有会话）与 `select()`（用户点选工作台）都不调用 `reapply()`；`reapply()` 在 allow 为空或只剩 `request_tool` 时直接跳过并记警告。
- **理由**：桌面端装上插件的当轮出现了真实故障：`attach()` 时状态里还没有解析出的工具集，`restrict({allow:["request_tool"]})` 把可见集清空；DSH 的 in-history 投影会把历史工具标成 `defer_loading`，服务端返回 `400 INVALID_REQUEST: tools: at least one tool must have defer_loading=false. All tools cannot be deferred.`。掩码本来就应该绑在「这一轮要发哪些工具」上，`turn/start` 正是唯一能拿到已解析工具集的时点。
- **代价**：插件热装到已运行的会话后，若该会话不再发消息，它保持原工具集；这是想要的行为。多一条守卫后，工具集从未解析成功的会话会一直不掩码，日志里有警告可查。
